 ⚠️  COMMON MISTAKES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

❌ DATABASE_URL not set
   → App tries localhost, fails
   → FIX: Go to Web Service Settings → Environment, add DATABASE_URL

❌ Start command wrong
   → No quotes around app:create_app('production')
   → Missing 'production' parameter
   → FIX: gunicorn -w 4 -b 0.0.0.0:$PORT "app:create_app('production')"

❌ Using database URL from wrong service
   → Used external URL instead of internal
   → FIX: Use "Internal Database URL" from PostgreSQL service

❌ Different region for web and database
   → Connection latency
   → FIX: Select same region for both services

❌ Not waiting for deployment
   → App still deploying when you test
   → FIX: Wait for "Live" status, watch logs

PROBLEM: "connection to server at localhost failed"
FIX:
  1. Go to Web Service Settings
  2. Check Environment section for DATABASE_URL
  3. Value must start with postgresql://
  4. Click Save and Redeploy

PROBLEM: "Worker failed to boot"
FIX:
  1. Check Build Logs tab
  2. Look for Python syntax errors
  3. Verify all imports work locally
  4. Run: pip install -r requirements.txt

PROBLEM: App doesn't load / blank page
FIX:
  1. Check Logs tab for errors
  2. Try /api/health endpoint
  3. Check browser console (F12)
  4. Verify DATABASE_URL set

PROBLEM: Database empty / no tables
FIX:
  1. This is NORMAL - tables auto-create on first /api/assess request
  2. Just use the app - tables will appear
  3. Check with: SELECT * FROM information_schema.tables
